--------------------------------------------------------------------------------
INCIDENTES Y RESOLUCIONES
--------------------------------------------------------------------------------

1. AmbiguousParameter en extractor de orders

   Síntoma:
     psycopg.errors.AmbiguousParameter: could not determine data type
     of parameter $2

   Causa:
     Cuando watermark_id = None, PostgreSQL no puede inferir el tipo
     del parámetro en la condición:
       (order_date = :wdate AND order_number > :wid)

   Solución:
     Usar string vacío en lugar de None:
       wid = watermark_id if watermark_id is not None else ""
     Como cualquier string es > "", la condición funciona igual.

2. AttributeError en el bloque except del runner

   Síntoma:
     'int' object has no attribute 'status'

   Causa:
     PipelineRun.__table__.select() no devuelve una entidad ORM
     mapeada. db.scalar() devolvió un entero.

   Solución:
     Usar select(PipelineRun).where(...) que sí devuelve ORM.

3. Typo en el nombre del archivo __main__.py

   Síntoma:
     No module named app.pipeline.__main__

   Causa:
     El archivo se creó como __main__,py (con coma en lugar de punto).

   Solución:
     git mv + ren para renombrar el archivo.

4. Watermarks/runs colgados en RUNNING

   Síntoma:
     Después de los bugs, quedaron registros en estado RUNNING.

   Solución:
     UPDATE manual a FAILED con mensaje descriptivo.

--------------------------------------------------------------------------------
DECISIONES TÉCNICAS TOMADAS
--------------------------------------------------------------------------------

1. RAW como copia fiel, sin transformaciones.
2. Enums de origen guardados como String en RAW (tolerancia).
3. UUID como UUID(as_uuid=False) (string) en RAW.
4. Metadata de ingesta en 5 columnas (_raw_id, _source_id,
   _ingested_at, _ingestion_run_id, _source_table).
5. UPSERT por _source_id para idempotencia.
6. Watermarks con (last_date, last_id) para orden determinista.
7. Full load para customers (10,000 filas, no vale incremental).
8. Incremental para orders y order_items por order_date.
9. Dos engines SQLAlchemy: source (solo lectura) + target (RW).
10. SQL puro (text) en extractores por flexibilidad y velocidad.
11. run_id único por corrida del pipeline.
12. Transacción por entidad, con rollback en caso de error.
13. Modelos del origen definidos localmente (desacoplamiento).
